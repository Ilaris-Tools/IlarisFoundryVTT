## Context

Non-instant Pre-Effects currently create a fresh spell-named embedded
ActiveEffect for every successful cast. The semantic resolver applies the
Ilaris strongest-effect policy only to `system.ilarisModifiers`; it does not
mutate documents, so the existing behavior correctly preserves weaker effects
for later restoration. The world setting's `foundry` mode only bypasses that
resolver suppression today, meaning recasts of the same spell add instead of
replacing each other.

The reviewed Psychostabilis and Tanz des Ungehorsams effects use the native
`system.abgeleitete.mr` change. Native Foundry changes are applied outside the
semantic resolver, so those effects do not currently obey either mode's
supernatural stacking policy.

## Goals / Non-Goals

**Goals:**

- Preserve all applied supernatural recasts in default Ilaris mode.
- Replace the entire prior persistent effect set from one supernatural source
  when Foundry mode is selected.
- Give MR the same semantic prepare and supernatural-stacking lifecycle as
  existing GS modifiers.
- Retain existing owner-turn timing, amplification, resistance, and
  suppression-ledger behavior.

**Non-Goals:**

- Do not alter how different spells stack in Foundry mode; they remain
  additive.
- Do not replace effects merely because they share a display name; source UUID
  provenance remains the replacement boundary.
- Do not change Vorteil behavior: all Vorteil modifiers remain permanently
  ordinary and additive.
- Do not add a new combat hook, change owner-turn duration semantics, or
  make native general-purpose `changes` participate in semantic resolution.
- Do not redesign Pre-Effect authoring or perform a broad migration of every
  existing spell.

## Decisions

### Persist source and application identity with each created spell effect

`applyPreEffects()` will enumerate the source Pre-Effects and generate one
application ID per target and cast. It passes both that ID and the source
component index through direct and resist-delayed creation paths. Each created
ActiveEffect stores `flags.ilaris.preEffectIndex` and
`flags.ilaris.applicationId`, together with existing `sourceType` and
`spellUuid` provenance. The replacement source identity is:

`sourceType === "uebernatuerlich" + spellUuid`

The application ID distinguishes effects generated by the new cast from
earlier casts. It ensures that a spell with several durable Pre-Effects keeps
every component created by the new application, including components resolved
later after a resistance test. The component index remains provenance for
authoring and inspection, not replacement identity.

### Apply the policy at the common persistent-creation boundary

`createActiveEffectFromPreEffect()` is the one path used after a normal cast
and after a resolved resistance test. It will read the world stacking setting
immediately before persistence:

- `ilaris`: call the existing creation flow without deleting old effects.
- `foundry`: find all prior supernatural embedded ActiveEffects with the same
  source UUID on the target actor, delete their IDs, then create the new
  document. Effects from the current application ID are retained.

The delete operation is awaited before creation so a re-cast cannot
temporarily double the contribution. The implementation will use the
documented [Actor#deleteEmbeddedDocuments](https://foundryvtt.com/api/v14/classes/foundry.documents.Actor.html#deleteEmbeddedDocuments)
operation rather than direct collection mutation. Older effects without an
application ID are deliberately replaced when the same source is recast, so
they cannot leave stale components beside the new application.

### Model MR as a semantic prepare target

Add canonical target `mr` to the Ilaris modifier constants, labels, editor
options, and Pre-Effect authoring options. The actor's existing semantic
preparation step will resolve both GS and MR from
[Actor#allApplicableEffects](https://foundryvtt.com/api/v14/classes/foundry.documents.Actor.html#allApplicableEffects)
and add the resulting value only to prepared `system.abgeleitete.mr` data.
No actor update is persisted during preparation.

The three reviewed MR source Pre-Effects will become prepare-phase,
`strongest-supernatural` semantic MR modifiers and no longer emit their native
MR change. This is preferred over special-case duplicate detection for native
changes because it makes both positive and negative MR effects follow the same
sign-separated strongest-effect rule and Foundry-mode behavior as every other
semantic supernatural modifier.

### Keep source data and UI wording consistent with behavior

The German setting description will state that Ilaris mode keeps all cast
effects while resolving the strongest overlap, whereas Foundry mode replaces
all prior ActiveEffects from the same supernatural source and otherwise adds
effects. The short
reference will explain the same distinction, including that the visible
replacement is an effect document replacement rather than a suppression.

## Risks / Trade-offs

- A weaker Foundry-mode recast replaces a stronger one: this is the explicit
  selected policy. The newest casting replaces the earlier source application
  and refreshes its duration.
- Legacy effects are removed by a new Foundry-mode cast: all prior
  supernatural effects with the same source UUID are deliberately replaced,
  preventing stale source components from persisting.
- MR preparation runs after dependent values are used: keep the existing
  `prepareData()` boundary and add a focused actor fixture assertion that the
  prepared MR includes only the resolved semantic value.

## Migration Plan

1. Add component and application flags and propagate them through normal and
   resistance application paths.
2. Add the Foundry-mode replacement branch at the shared creation boundary.
3. Add semantic MR support, then migrate only the three reviewed source
   Pre-Effects.
4. Update setting and guide text, run `npm run pack-all`, and validate packed
   output.
5. Run unit tests, lint, and E2E verification in `schwarzpulver`.

No migration of existing embedded ActiveEffects is performed. Rollback is a
code/data revert; old effects remain valid documents.

## Testing Strategy

- Use pure resolver tests for MR target matching, separate strongest positive
  and strongest negative candidates, and Foundry-mode additive selection.
- Use the existing Jest global Foundry mocks in
  `pre-effects-processor.spec.js` to assert ordered deletion and creation,
  direct versus resistance provenance, whole-source replacement, and
  preservation of components from the same new application.
- Extend actor-data tests using the repository's existing direct instance or
  `Object.create` pattern to check transient MR preparation.
- In Foundry E2E, use a GM and one target in `schwarzpulver`: inspect both
  retained effects in Ilaris mode; then switch to Foundry mode and verify a
  recast replaces all effects from the earlier source application while
  retaining every component of the new application. Repeat with an MR source
  effect.
